## Resumen ejecutivo de bugs corregidos

5 correcciones, todas verificadas con la suite (28/28 tests en verde tras los cambios, incluidos 3 tests de regresión nuevos): el flag `--dry-run` a secas no mostraba el plan de ejecución que la documentación promete; el escáner SUID daba falsos positivos al marcar como vectores de root binarios cuyo dueño no es uid 0; la función de impresión filtraba salida en modo `--quiet`; el comando mostrado por el vector cron tenía el quoting roto y un operador que lo copiara ejecutaba basura; y la comprobación de escritura ignoraba que root puede escribir todo. No se ha encontrado ninguna vulnerabilidad crítica de seguridad; hay una nota de modelo de amenazas sobre la base GTFOBins persistida que se documenta como riesgo aceptado.

## Detalle por corrección

### 1. `--dry-run` sin `--exploit` no mostraba el plan

- **Severidad:** media (bug funcional, contradice la ayuda y ambos README).
- **Causa raíz:** en `main.go` la condición era `if p.Opts.Exploit && p.Opts.DryRun`, de modo que `--dry-run` solo entraba en la fase 3 y el plan nunca se imprimía. Verificado empíricamente antes del fix (0 líneas de plan en la salida).
- **Solución:** `if p.Opts.DryRun { printDryRunPlan(p); logDryRun(p.Opts) } else if p.Opts.Exploit { ... }`. La combinación `--exploit --dry-run` sigue mostrando el plan sin explotar, y el código de salida no cambia (el guard de exit 1 mantiene su condición sobre `DryRun`).
- **Archivos modificados:** `main.go`.
- **Verificación:** `./autoprivilege --dry-run` imprime ahora el plan "safest first" (comprobado en ejecución real, exit 0).

### 2. SUID sin comprobación de propietario uid 0 (falso positivo)

- **Severidad:** media (integridad de resultados; el proyecto se vende como "honest results").
- **Causa raíz:** `scanSUID` consideraba explotable cualquier binario con el bit SUID que tuviera técnica GTFOBins, sin comprobar que el dueño sea root. Un binario SUID propiedad de uid 1000 escala a ese usuario, nunca a uid 0.
- **Solución:** nueva función testeable `classifySUID(bin, ownerUID)` en `scanner.go`: solo root-owned + técnica conocida es vector (HIGH para shells, LOW para el resto). Los no explotables se conservan como hallazgo informativo (contan en el JSON, no se imprimen) y los no-root indican "owner uid N — not a root vector".
- **Archivos modificados:** `scanner.go`, `autoprivilege_test.go` (nuevo `TestClassifySUID`).
- **Verificación:** `go test -run TestClassifySUID -v`; comportamiento del escáner re-verificado en ejecución real (los SUID del contenedor siguen clasificándose correctamente).

### 3. `Print()` filtraba hallazgos en modo `--quiet`

- **Severidad:** baja (contrato de la CLI: "`--quiet` no output; exit code only").
- **Causa raíz:** `Print` solo silenciaba los hallazgos NO explotables (`if p.Opts.Quiet && !finding.Exploitable { return }`); cualquier llamada con un hallazgo explotable imprimía en quiet. Los puntos de llamada actuales lo enmascaraban con guards externos, pero era una trampa para cualquier código futuro.
- **Solución:** `if p.Opts.JSON || p.Opts.Quiet { return }` al inicio de `Print`.
- **Archivos modificados:** `universe.go`, `autoprivilege_test.go` (nuevo `TestPrintQuietRespected`, con captura de stdout mediante pipe).
- **Verificación:** `go test -run TestPrintQuietRespected -v` — quiet imprime "" y el modo normal sigue imprimiendo.

### 4. Comando mostrado del vector cron con quoting roto

- **Severidad:** baja (el exploit real en Go escribía el payload correctamente; lo roto era el comando que se muestra en `--dry-run`, en `[manual]` y en el informe markdown, y que un operador copia a mano).
- **Causa raíz:** el payload del cron contiene comillas simples (`bash -c '...'`), y el comando mostrado era `echo '<payload>' >> <file>` — comillas simples dentro de comillas simples.
- **Solución:** el comando mostrado usa ahora un heredoc citado (`cat >> <file> <<'AUTOPRIV_EOF' … AUTOPRIV_EOF`), que preserva el payload byte a byte sin expansiones. Test de round-trip que ejecuta el comando mostrado contra un fichero temporal y comprueba que el payload aterriza intacto.
- **Archivos modificados:** `enumerate.go`, `autoprivilege_test.go` (nuevo `TestCronVectorCommandQuoting`).
- **Verificación:** `go test -run TestCronVectorCommandQuoting -v`.

### 5. `isWritableByCurrentUser` ignoraba euid 0

- **Severidad:** baja (afecta a ejecuciones como root, donde la herramienta no va a escalar, pero producía clasificaciones incorrectas en el JSON).
- **Causa raíz:** la función evaluaba solo los bits de permiso; para root (euid 0) el kernel ignora esos bits y todo es escribible, así que un `/etc/shadow` 0444 se reportaba como no escribible siendo root.
- **Solución:** cortocircuito `if os.Geteuid() == 0 { return true }` al inicio de la función. Sin test unitario: no se puede asumir euid 0 en CI; la lógica es una línea y queda documentada en el código.
- **Archivos modificados:** `scanner.go`.
- **Verificación:** razonamiento documentado + suite completa en verde (ningún test asumía el comportamiento anterior para root).

## Bugs/vulnerabilidades detectados pero NO corregidos aún

- **Interleaving cosmético stdout/stderr en pipes:** al capturar la salida con pipes, las líneas de log de stderr pueden intercalarse a mitad de línea con las de stdout (observado con `--dry-run` en esta ronda). Severidad baja; en terminal real no ocurre porque son streams separados. Motivo de no corrección: requiere reordenar el logging (p. ej. todo a stderr o buffer por fases); se deja como candidato de pulido, no de seguridad.
- **Base GTFOBins persistida como vector de ejecución (modelo de amenazas, riesgo aceptado):** `~/.autoprivilege/gtfobins.json` (o `$AUTOPRIV_DB_DIR`) alimenta comandos que `--exploit` ejecuta vía `/bin/sh`. Quien pueda escribir ese fichero ya ejecuta código como el usuario, así que no eleva privilegios por sí mismo; el fichero se escribe con 0600 y el directorio con 0700 (correcto). Documentado aquí para que futuros agentes no lo "endurezcan" sin necesidad ni lo rompan asumiendo que es input de confianza.
- **`cleanGTFOCmd` no valida que el comando descargado sea inocuo:** por diseño la herramienta ejecuta técnicas de explotación; el contenido de upstream GTFOBins se considera de confianza del operador. Sin cambio.

## Recomendaciones de seguridad generales para el resto de agentes

- Mantener el patrón `runCmdOut` con timeout en cualquier llamada a comandos externos nueva: evita que un entorno de laboratorio colgue el escáner.
- Cualquier comando mostrado al operador (dry-run, manual, informes) debe ser copy-paste seguro: usar heredocs citados o escapado explícito cuando el payload contenga comillas o `$`.
- Al añadir escáneres, no marcar `Exploitable: true` sin una condición verificable (el estándar lo pone ahora `classifySUID`); los hallazgos informativos van con `Exploitable: false`.
- No persistir nunca datos descargados fuera de `~/.autoprivilege` con permisos más amplios que 0600/0700.
