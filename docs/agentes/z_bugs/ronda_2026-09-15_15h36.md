## Bug detectado y corregido en esta ronda

### Barra de distribución de riesgos del HTML apuntaba al bucket equivocado (MEDIO, cazado pre-commit)

- **Síntoma:** `htmlSummary` mapeaba la clase CSS `info` al bucket `INFO`, pero `buildSummary` escribe los buckets con `RiskLevel.String()` — el bucket de los hallazgos informativos se llama **`SAFE`**, nunca `INFO`. En un host con hallazgos informativos, la barra los habría omitido silenciosamente mientras la línea de texto inferior sí los lista — la imagen y el texto de la MISMA tarjeta habrían discrepado.
- **Detección:** revisión línea a línea del render contra el contrato del JSON de la ronda 9 (los buckets son exactamente `SAFE/LOW/MEDIUM/HIGH/DANGER`).
- **Corrección:** la barra itera ahora pares `(bucket, clase)` explícitos con `SAFE → clase info`; comentario en el código explicando el mapeo para que el próximo segmento no reintroduzca el fantasma.
- **Verificación:** suite completa en verde tras el parche; el screenshot del navegador regenerado muestra la barra coherente con la línea de distribución.

## Revisión de seguridad de lo añadido en esta ronda

### `--html` (la superficie XSS nueva)

- **Escape exhaustivo verificado por test:** todo valor dinámico (target y description de findings, source, host, user, version, comandos de vectores, línea de riesgos) pasa por `html.EscapeString` antes de tocar el documento. El test inyecta `<script>alert("xss")</script>` como TARGET (los targets son rutas de ficheros que un atacante puede nombrar), `<img src=x onerror=alert(1)>` como DESCRIPTION (las descriptions embeben contenido de ficheros) y markup en nombre de vector — verifica que el HTML solo contiene las entidades escapadas, jamás el markup crudo.
- **Superficie de ataque honesta:** el informe es un fichero 0600 en un directorio del operador con contenido leído del propio host; el vector realista es exactamente el probado — un fichero de credenciales/hostil cuyo texto incluye HTML. Con el escape, se renderiza como texto. El CSS es estático (sin interpolación), sin JavaScript, sin recursos externos (test prohíbe `http://`/`https://` — también elimina el leak de URLs por referencia a assets).
- **Permisos y atomicidad heredados:** 0600 FIJADO por `atomicWriteFile` (test con verificación de modo) y cero restos `.tmp` (test de integración) — el informe lista vías de escalada; la misma propiedad que protege al JSON protege a la página.

### `--fail-on-new [riesgo]` (nueva semántica de puerta)

- **Fail-fast en TODAS las variantes (E2E real):** `--fail-on-new=bogus` → el parser del flag rechaza con error y exit 2 ANTES de escanear (verificado con binario real); bare sin `--baseline` → exit 2 con mensaje que explica la dependencia (verificado); con baseline y umbral inválido → exit 2 (verificado). Una puerta mal configurada nunca pasa en silencio ni escanea de balde.
- **Contrato ronda 11 preservado bit a bit (re-testeado):** bare = cualquier explotable nuevo; informativo nuevo no tripa; ambas puertas tripan → 3 con precedencia del mensaje de la puerta de política; puertas en verde → caída al 0/1 clásico (contrato ronda 8).
- **Umbral sin bypass:** no existe variante que desactive la puerta por accidente; `Set("true")` es equivalente a bare (afirmación explícita, no bypass); el conteo itera `Diff.New` (estado final post-scan, post-reportes) — el pipeline falla 3 con todos los artefactos disponibles.

### Cadena de medios (no es código del producto, pero se audita igual)

### Refactor `registerFlags`

- **Equivalencia verificada:** la extracción del registro a función pura mantiene el ORDEN y los textos idénticos (el usage se genera aparte, el test de paridad cruza ambos); `run()` y el test comparten la misma fuente — el fallo de hermeticidad (flags `test.*` del framework contaminando la comparación) queda cortado por construcción al usar un FlagSet privado.
