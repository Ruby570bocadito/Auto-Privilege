## Detalle por mejora

### Mejora 1 — Modo diff `--baseline report.json` (R40)

- **Nuevo módulo `diff.go`:** `loadBaseline` (lectura + validación fail-fast: JSON inválido o fichero ajeno → error claro y exit 2 ANTES de escanear), `diffReports` (clasificación new/resolved con clave `Source+Target` — robusta a reordenaciones y cambios de redacción; dedup por lado; `New`/`Resolved` nunca nil; `SummaryBefore.Risks` normalizado a `{}`) y el tipo `ReportDiff` (`baseline_path`, `baseline_date`, `new`, `resolved`, `new_exploitable`, `summary_before`).
- **Integración en las tres salidas:** el JSON de `--json`/`--output` incorpora la clave `"diff"` (`omitempty` cuando no hay baseline — sin nulls); el markdown de `--report` gana la sección `## Diff vs baseline` con métricas y tabla de hallazgos nuevos (determinista: filas en orden de escaneo, nunca iteración de mapa); el terminal imprime el bloque `── Diff vs baseline ──` (recuentos + cada hallazgo nuevo con los tags de riesgo estándar vía `p.Print`, silencioso en `--json`/`--quiet`).
- **Verificación real:** snapshot con `--output base.json` → se crea `~/.sh_history` con secretos → re-scan con `--baseline` muestra EXACTAMENTE 1 nuevo (1 explotable) con su tag `[!] CRED`; el JSON contiene `diff` con las 6 claves; el markdown muestra la sección; baseline corrupto (`/etc/hostname`) → exit 2 con mensaje; sin baseline la clave `"diff"` no existe en el JSON.

### Mejora 2 — Puerta de política `--fail-on <risk>` (R41)

- **`parseFailOn`:** vacío deshabilita; low/medium/high/danger fijan el umbral (case-insensitive, igual que `--risk`); `safe` se rechaza a propósito (sería un alias confuso de low: todo hallazgo tiene riesgo >= SAFE) con mensaje que sugiere la alternativa; basura → error con los valores válidos. Validación fail-fast antes del banner (exit 2).
- **`policyGateCount`:** cuenta SOLO hallazgos explotables con `Risk >= umbral` (los informativos no tripan la puerta — es un gate de superficie accionable, no de ruido).
- **Exit code 3, evaluado al final y con precedencia:** el gate se evalúa tras escribir TODOS los reportes (JSON, markdown, output) y gana sobre el 1 de "exploit sin root" — un pipeline debe fallar aunque el exploit también haya fallado. Mensaje a stdout en modo humano; **a stderr en `--json`/`--quiet`** para no romper a los consumidores `jq` del stdout.
- **Verificación real:** `--quiet --fail-on low` en este host → exit 3 con "2 exploitable finding(s) at/above LOW" en stderr (y demuestra la precedencia: `--quiet` implica `--exploit` sin root, que sería exit 1, pero el gate gana); `--fail-on danger` sin hallazgos DANGER explotables → exit 1 intacto; `--fail-on safe` → exit 2.

### Mejora 3 — Scanners `PRELOAD` y `SUDOERS` (R42)

- **`scanPreloadPaths` (`scanner.go`):** `/etc/ld.so.preload` no vacío → hallazgo PRELOAD; escribible → HIGH explotable ("entries injectable"), si no → LOW informativo (honestidad: entradas configuradas por otro son pista de investigación, no ruta del usuario actual). Recuento de entradas con `countPreloadEntries` (líneas no-blank — glibc ignora las blancas); **el contenido jamás se imprime**, regla "presencia, no contenido" de los scanners de credenciales. Árbol sudoers: `/etc/sudoers` escribible → SUDOERS HIGH explotable; `/etc/sudoers.d` (directorio) escribible → SUDOERS HIGH explotable. Rutas inexistentes o permiso-negado → silencio honesto. Los paths viven en `preloadPaths` (sobrescribible en tests; producción siempre ve `/etc`).
- **Enumeración (`enumerate.go`):** `preload` → vector MANUAL (la inyección exige compilar un .so en el objetivo — la herramienta muestra la técnica y declara el requisito de gcc en la nota, no finge haber construido nada); hallazgo informativo no genera vector. `sudoers` con target `/etc/sudoers` → vector AUTO (`exploitSudoersWrite`); `sudoers.d` → vector MANUAL con la advertencia honesta de que sudo ignora drop-ins que no son de root. Cableado completo: `validVectors`, ambos switches de enumeración, `--vector` (flag y usage), y fuentes añadidas a la tabla de simetría estructural (`TestVectorSelectionSymmetry` exige que cada nombre produzca solo su categoría).
- **`exploitSudoersWrite` (`exploit.go`):** append idempotente (`sudoersRulePresent` reconoce ambos espaciados de `NOPASSWD: ALL`) de la regla `ALL ALL=(ALL) NOPASSWD: ALL` + intento `sudo -n -i` reutilizando `exploitSudoALL`. **Seguridad de la escritura:** si el fichero no acaba en `\n`, se compensa antes del append — concatenar sobre la última línea sería un error de SINTAXIS sudoers que dejaría sudo roto para todo el host (el fallo peligroso de este vector). Resultado honesto en tres ramas: root conseguido / regla activa / regla escrita pero sudo falló (con el error real).
- **Verificación real end-to-end:** namespace `unshare -r -m` con `/etc` sintético bind-monteado (sudoers 0666, sudoers.d 0777, ld.so.preload con 2 entradas): el binario real con `--json --vector preload,sudoers --dry-run` reporta PRELOAD HIGH explotable + SUDOERS en ambos targets, vectores de categoría exclusivamente preload/sudoers, comando del sudoers con la regla exacta. `/etc` real jamás tocado (stage en temp, limpiado).
