## Detalle por mejora

### Mejora 1 — `summary` en el informe JSON

- **Motivación:** el ejemplo de ambos READMEs (`autoprivilege --json --quiet | jq '.summary'`) devolvía `null` porque `jsonReport` no tenía ese campo. Era la promesa documentada más visible incumplida.
- **Archivos modificados:** `report.go` (nuevo tipo `jsonSummary`, nueva función `buildSummary`, campo `Summary` en `jsonReport`), `autoprivilege_test.go` (nuevo `TestJSONSummary`).
- **Forma del bloque:** `findings`, `exploitable`, `vectors`, `auto`, `manual`, `risks` (mapa por nivel, con los niveles sin hits omitidos para igualar el resumen del terminal y nunca `null`) y `rooted`.
- **Cómo probarla:** `go build -o autoprivilege . && ./autoprivilege --json | jq '.summary'` → devuelve el bloque de contadores. Test: `go test -run TestJSONSummary -v`.

### Mejora 2 — Workflow de release con binarios reales

- **Motivación:** el README enlaza `releases/latest/download/autoprivilege-linux-amd64`, pero no existía ningún job que construyera y publicara esos ficheros: el enlace es un 404 para cualquier usuario que siga la guía de inicio rápido.
- **Archivos creados:** `.github/workflows/release.yml`.
- **Comportamiento:** al empujar un tag `v*` ejecuta la suite de tests, construye `autoprivilege-linux-amd64` y `autoprivilege-linux-arm64` con `CGO_ENABLED=0 -trimpath -ldflags "-s -w"` (estáticos, nombres exactamente los que descarga el README), hace smoke test de `--version` y los adjunta al release con notas generadas.
- **Cómo probarla:** `git tag v1.2.0 && git push origin v1.2.0` → la pestaña Actions ejecuta el workflow y el release publica los dos binarios. (Queda a decisión del mantenedor crear el tag; esta ronda no etiqueta por sí sola.)

### Mejora 3 — Vectores para todos los hallazgos CRED

- **Motivación:** los escáneres marcan como explotables las claves SSH, la metadata cloud, los history con secretos y las configs con contraseñas, pero `enumerateCredential` solo generaba vector para las claves SSH. El resto de hallazgos CRED no aparecía en el plan `--dry-run` ni en la sección de vectores del informe markdown: el operador perdía exactamente las pistas de credenciales, que suelen ser la vía más rápida a root.
- **Archivos modificados:** `enumerate.go` (ramas cloud-metadata / history / config en `enumerateCredential`, cada una con su comando manual seguro y metadatos `type`), `autoprivilege_test.go` (nuevo `TestEnumerateCredentialVectors`).
- **Cómo probarla:** `./autoprivilege --dry-run` en una máquina con history o configs con credenciales → aparecen los vectores `history …` / `creds …` / `cloud-metadata …` como `[manual]`. Test: `go test -run TestEnumerateCredentialVectors -v`.
